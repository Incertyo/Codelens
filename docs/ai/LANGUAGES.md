# Supported execution languages

The editor/Run boundary is Python-only, owned by src/lib/editor-language.ts. Monaco and both language selectors offer Python only; workspace runs and library/example loads are guarded to Python. Internal Language remains python | javascript for frozen catalog maintenance, existing API contracts and unchanged golden tools; internal dual-language runners are not selectable editor support. Public Python harnesses and protocol limits are unchanged by this behavior change.

`ShareLanguage` retains javascript/cpp/java for source-only old-link compatibility. Both compressed formats retain exact source/stdin. The workspace marks every non-Python share unsupported, disables Run, blocks analysis/cached-analysis loading and preserves its legacy language when re-sharing. New/load clears the marker; Undo New restores it. Editing alone does not reinterpret legacy source. Nothing executes automatically.

Underlying heuristic/model evaluation remains unchanged for internal maintenance. The editor maps JavaScript detection to unsupported and never auto-switches to it. Recognized non-Python drafts are blocked by a synchronous Run guard as well as the button state; ambiguous text runs only through Python and may produce a syntax error. Detection is finite; docs/DETECTION_EVAL.md remains the historical model comparison, not a universal language classifier. No transpiler or runtime fallback is added.

Only explicit notes and advice upload source plus bounded function/event/entry metadata. Stdin, stdout and runtime variable values remain local. Server schemas and provider fixtures retain their existing Python/JavaScript contract; the editor submits Python only and other API languages are rejected. mode=simulate returns 410 before provider configuration, shared admission or generation. Provider quotas, readiness cache, kill switch, validation/retry behavior and existing save/cache paths are unchanged. The persistence concern in REFACTOR_FINDINGS.md is not fixed here.

Python-only coverage: python-only.test.ts and e2e/python-only.spec.ts use real detection/share functions and actual Pyodide browser runs. Historical browser cases that expect selectable JavaScript require the explicitly authorized language-removal update; internal runtime/model/API/share goldens stay byte-for-byte unchanged. The full 360-record Python/JavaScript corpus remains.

No new runtime env variable, route or dependency. Smoke checks the sole Python selector option and a real Python trace; check:env keeps its names and validation. The installed ML model remains until a qualifying comparison and explicit removal approval.
