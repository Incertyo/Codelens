# Insights

Workspace tabs are Visualizer, Insights and Complexity. Insights contains Overview, Structure and flow, Run evidence and Review. The standalone Complexity tool retains its existing measurement/comparison features; Insights displays no cost estimates, copy/memory guesses or estimate-status text.

Validated AI is the primary explanation source. While the first response is pending, show Preparing AI notes rather than a main local report. If AI is disabled, unavailable, invalid or paused before notes arrive, show a clearly labelled Local code notes fallback from real Python AST output. Existing valid AI notes remain primary if an update/review fails. Missing AI prose is explicitly missing, never filled silently with a local heuristic.

use-insights.ts owns local source grounding, source/run-epoch identity, automatic notes/review, cancellation and explicit test execution. Local outline/inspection still use real workers and the existing debounce to validate metadata and support advice/test drivers; they are not the primary explanatory UI. The component stays mounted across tabs and remounts on source identity changes.

model/insights-report.ts builds the presentation model. AI summaries, function descriptions/returns and line explanations lead; local signatures, actual statement lines and function bounds ground references. AI walkthrough rows must match real AST statements. The local structure disclosure is available explicitly. Without AI, local descriptions and flow become the fallback. Hot spots always use matching real traces and remain labelled as observations for one input, not predictions.

Automatic notes and advice remain separate budgeted API modes, each with a readiness check. One attempt per source/run epoch; no automatic POST replay. Abort/discard on tab departure, source changes, Run, stdin or step-cap changes, including A-to-B-to-A edits. Partial/paused review status is explicit; a failed review never discards valid notes. Apply/undo and real-worker suggested-test checks stay explicit.

format=structured opts the new client into the current prompts; omitted format preserves frozen legacy request/prompt contracts. Structured prompts ask for explanations, not complexity estimates. A cosmetic heading value cannot reject an otherwise schema/reference-valid response or spend a retry. Shared insight-text accepts readable Unicode dashes; unusable headings are omitted in the UI instead of being replaced by an invented AI/AST algorithm identity. Strict Zod, actual function/line/step reference validation and counted retries for genuine invalid content remain.

Privacy notice discloses automatic source upload/provider terms. Requests contain source plus bounded function/event/entry descriptors, never stdin, output or runtime values. AI is off by default and retains readiness, kill switch, quotas and deadlines. AI text remains plain text and is not proof of correctness. No new variable, route, provider or dependency; frozen runtime/catalog/golden data untouched.

Tests: insights-report uses actual catalog programs through Pyodide outline/inspection/tracing; insight-generation uses real SDK plus local HTTP/limiter fixtures for cosmetic-vs-schema/reference errors and budget counts; structured-insights covers production workers, AI-first loading, genuine AST fallback, no estimates, partial/paused review, themes/mobile/axe. Existing automatic/quota/advice/identity/apply/undo/race/debounce/measurement assertions are migrated to source-mode selectors. The earlier cross-tab focus finding remains separate; its focus assertion is retained. Browser tests require a production build, never Next dev; no hosted calls in verification.
