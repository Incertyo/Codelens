# Phase 1 decisions

- **Scope:** implement only the named Phase 1. Breakdown and Analysis are navigable, explicitly labelled placeholders. JavaScript/C++/Java appear as unavailable language options. No LLM route or simulated traces yet; `.env.example` reserves the Phase 2 provider contract.
- **Runtime:** Pyodide and Monaco are installed through npm and copied into `public/` on installation. Fonts are bundled locally. No CDN or API key is needed at runtime. This means offline operation after local assets are available; this phase is not an installable PWA and does not promise a fresh visit without the local server.
- **Workers:** create a fresh worker per run, terminate it on completion, cancellation, or timeout. Fresh interpreters cost some startup time but prevent state and package changes leaking between runs. Runtime downloads use streamed byte counts from a generated manifest; initialization uses completed stages. The first-run counter shows actual progress, never a fabricated timer, and is skipped on repeat runs/visits while inline progress remains visible.
- **Limits:** 30,000 code characters; 10,000 stdin characters; at most 5,000 steps, adjustable down to 100 in the UI; 12-second external execution deadline; 90-second loading deadline. The tracer reserves its final step for a safety/error event. Each snapshot bounds variables (80), heap objects (128), collection elements (80), object nesting (6), call frames (80), strings (200 characters), and cumulative stdout (20,000 characters). Large integers become strings to avoid JavaScript precision loss.
- **Semantics:** `line` snapshots represent the state **before** executing that line. `call` snapshots include arguments; `return` snapshots include a `↳ return` entry. Print writes generate output steps, including writes of spaces/newlines. The last unhandled error is a final exception step at its source line; caught exceptions also appear as trace events. Imported library internals are not traced. User functions, comprehensions, and class-body events are traced.
- **Aliasing:** assign stable `hN` heap references from Python identities, retaining referenced objects for a run so recycled identities never alias incorrectly. Lists and nested-list matrices have dedicated visuals in this phase; dicts, sets, and class instances use expandable heap entries. Advanced node-link views and a recursion tree belong to Phase 2.
- **Security:** bootstrap trusted local assets before disabling worker `fetch`, XHR, importScripts, WebSocket, WebTransport, EventSource, worker creation, and window opening. These bindings are non-writable/non-configurable. Direct imports of browser bridge and package-install modules are rejected. Python cannot access the page DOM; code never goes to a server. Interpreter introspection is not a security boundary: this is a local educational sandbox, not a hardened hostile-code service. Browser memory use cannot be strictly bounded by a Web Worker; timeouts mitigate execution, not every possible allocation.
- **Design:** dark default; Space Grotesk, JetBrains Mono, and Doto. All theme, type, spacing, and motion tokens live in `src/app/globals.css`, exposed on `/design`. Yellow is paired with arrows, outlines, changed-value markers, or active-tab position. Light-mode small text/focus markers use ink for contrast. Native modal dialogs supply focus trapping, Escape dismissal, and return focus. Editor/playback scrolling is native; Lenis is scoped to the About dialog. Decorative GSAP/cursor code is lazy and unmounted under reduced motion.
- **Performance:** timeline indexes directly into the trace; no 5,000-row step list is rendered. Only current/previous snapshots are drawn. Heap and variable panels bound rendered data to tracer caps. Playback is independent from the execution worker. Do not claim 60 fps or a Lighthouse score without a measured browser result; record measurements in `docs/VERIFICATION.md`.
- **Sharing:** LZ-string compression in a hash stores code, language, and stdin. No server storage or execution state is shared. Clipboard failure opens a selectable-link dialog. Links are readable by anyone receiving them; users control what they share.
- **Tooling:** use Next's Webpack mode for predictable local Monaco loading. The lockfile records exact dependency versions. The npm registry installed newer compatible Next/React versions than the initial scaffold minimums; patched Monaco and Vitest versions are selected after audit.
- **Editor compatibility:** disable Monaco's experimental EditContext path and use its established textarea input, so paste and keyboard editing work consistently. Capture Ctrl/⌘+Enter before editor shortcuts. Monaco reads its typography and grayscale theme from the same CSS variables as the page; matrices are prioritized over supporting one-dimensional lists.
- **Tests:** real Pyodide unit fixtures, plus real browser-worker Playwright tests. No mock Python interpreter or server evaluation. Native browser tests cover runtime errors, timeouts/recovery, alias snapshots, stdin, all seven examples, breakpoints, sharing, accessibility, and responsive layout.

## Phase 2 decisions

- **Scope:** implement JavaScript, advanced structures, AST Breakdown, and optional AI notes. Analysis, complexity/empirical measurement, optimized diffs, other-language simulation, and deployment work remain Phase 3.
- **JavaScript execution:** parse synchronous scripts with Acorn, instrument the AST, regenerate source with Astring, and execute in strict mode only inside a disposable browser worker. `line` events occur before statements/loop conditions; calls/returns carry stable invocation IDs. Destructuring, classes, closures, expression arrows, loops, Maps/Sets, and the seven translated examples run with real JavaScript semantics. Imports, async/await, Promise-based asynchronous code, generators, and `with` are explicitly rejected. Caller locations are restored after returns, and exception origins survive cleanup; thrown `undefined` remains an exception. The optional global stdin helper can be shadowed by ordinary `input` declarations; a trailing newline terminates a value rather than inventing another input line.
- **Safety:** JavaScript uses the same code/step/value/output limits and external 12-second deadline as Python. Network and timer APIs are locked down before execution; a native dynamically constructed loop is still terminated externally. These educational workers are not hardened hostile-code isolates. Accessors are displayed without invoking them; proxies and native operations can still consume time or memory. JavaScript `undefined`, nonfinite numbers, and BigInt preserve their kinds through typed heap records.
- **Common trace:** add an optional `callStack[].id` to the shared Step format in both languages. Old traces remain compatible. Every recursive invocation has its own arguments/return event, so the recursion view distinguishes repeated calls to the same function.
- **Static breakdown:** Python uses `ast.parse` in a worker without executing source; JavaScript uses Acorn in its worker. Functions, loops, branches, classes, annotations, parameters, and return expressions come from ASTs. Summaries/algorithm labels use transparent static heuristics, with a reminder to verify behavior through the trace. Bubble-sort labels require a real two-value swap, not merely nested loops or comments. Source changes invalidate cached AST/AI data; old asynchronous results are ignored.
- **Advanced visuals:** detect shapes from captured references (`next`, `left/right`, `children/neighbors`, adjacency dictionaries/maps) and render SVG node links. Collections receive maps/sets and queue/stack/heap views; queue/stack/heap names are documented conventions, not proof of abstract data-type invariants. Cycles are visited once. Linked-list diagrams include other live pointers so reversal can show disconnected halves. Node-link diagrams cap at 80 nodes and visible structures at 6. The recursion scene includes every captured call, draws only nodes near the viewport plus active frames, and follows the current frame; no calls are dropped. All scroll areas have keyboard focus, and global shortcuts yield to native scrolling and buttons.
- **Language selection:** selecting a language translates an untouched example; custom source and stdin are preserved. All seven examples have authored Python and JavaScript versions. Hash shares include the selected language. No automatic AI translation is performed.
- **AI gateway boundary:** all optional enrichment uses `/api/analyze` with the installed AI SDK 7 and OpenAI, OpenAI-compatible, Anthropic, or Google adapters selected by `LLM_PROVIDER`. `LLM_API_KEY` and `LLM_MODEL` are required for enrichment; no model or paid request is silently chosen. `LLM_BASE_URL` is an optional trusted server configuration for compatible endpoints. Only the explicit enrichment button sends source and a bounded set of event metadata; stdin, output, and variable values are not uploaded.
- **Validation/fallback:** request and output schemas are strict Zod JSON schemas. AI summaries/functions/annotations/step notes are validated again against supplied source lines and sampled trace indices. Invalid output is retried once, with an 18-second total deadline. Failed/malformed output leaves the entire static Breakdown and trace available. AI text never replaces AST structure or becomes executable HTML/code.
- **API limits:** code max 30,000 characters; streamed request body max 200,000 bytes; 5 requests/client/minute and 30 requests/process/minute; client buckets capped at 1,024. A global ceiling also bounds requests when forwarded client headers are rotated. This in-memory limiter is appropriate to this local phase; distributed deployment controls belong to Phase 3. No secrets or snippets are logged or sent back in provider errors.
- **Provider verification:** no live API key was supplied. Tests run the actual SDK against a local compatible HTTP fixture with a test key, exercising malformed JSON retry, strict schema failure, invalid source references, valid enrichment, and secret exclusion. Browser tests also cover the AI UI contract using intercepted fixture responses. These are explicitly distinguished from live provider/model testing.

## Phase 2.5 — Algorithmic detection and canvas

The data path is source → reusable source hints → real Worker snapshots → `detectVisualModels` → modular React/SVG views. Detection/rendering is entirely client-side; this phase adds no execution API, AI request, or server analysis. The detector is pure and visits globals and every live frame, with local bindings taking precedence when binding that frame's pointers. Heap references deduplicate aliases. Specialized views precede ordinary sequences/maps; at most six primary views are drawn, with window overlays attached to their target.

Source evidence is a bounded lexical scan with comments/literals masked and language-specific pop/string rules. It is compiled once per source/language version, never per scrub tick. It does not prove exclusive mutations through aliases, dynamic dispatch, arbitrary expression dependencies, or algorithm correctness. Generic maps, matrices, linked nodes, binary trees, and graphs remain available when specialized evidence is absent. Scope/name conventions are transparent heuristics.

All diagrams bound nodes or visible cells to 80, preserve the existing heap/depth/frame limits, and use native keyboard-scroll regions. DP and generic matrices apply an aggregate 80-cell render budget instead of rendering 80×80 cells. Recursion keeps its prior viewport behavior. Large strings/collections show captured prefixes and omit pins beyond the drawn prefix; no missing cells are invented. Python Queue/LifoQueue/PriorityQueue snapshots capture the internal bounded queue contents without mutex/condition internals or invoking queue removals.

When no complex view exists, numeric/boolean/null/typed primitive variables are promoted into the Scalar State Monitor. All strings and arrays have a sequence fallback, including empty values. The no-collections state is reserved for a frame with no captured displayable variables. Pins, set bits and active cells pair yellow with labels, indices or shape; yellow always uses ink text. Focusable overflow areas retain keyboard scrolling. Reduced-motion mode disables the new animation durations/layout motion.

Verification adds `tests/detectors.test.ts` and `tests/visualizers.spec.ts`, preserving the existing suites. The performance script executes actual JS workers to collect 5,000 steps, then issues native timeline changes through each new view with full motion; its report distinguishes measured refresh intervals from device-independent performance guarantees. See `PHASE_2_5_VERIFICATION.md` for the completed measurements. Phase 3 remains paused.

## Phase 3 — Analysis, opt-in simulation and production preparation

These decisions supersede earlier Phase 3 placeholders. All prior execution, snapshot, size, privacy and honest-labelling limits remain.

1. **Identity:** every Analysis session/result belongs to implementation id plus SHA-256 of exact source. Loaded code keeps its immutable database id; edited/pasted code uses `draft:<language>` plus its hash. Source/language/implementation changes remount the component synchronously before async hashing completes, cancelling old workers and provider requests. Server/client reject mismatched hashes. Real traces carry source identity; heatmaps require the current identity.
2. **Static analysis:** Python ast.parse and Acorn run in browser workers without evaluating inspected source. Per-function loop nesting supplies explicitly conditional time candidates only when bounds are recognized. Calls, recursion, nested functions, unresolved bounds and allocations retain Unknown where appropriate. Best/average cases remain Unknown. Constant-cost expressions and at-most-n visits are disclosed assumptions; no proof of general complexity is claimed.
3. **Entry signatures:** exactly one required synchronous top-level identifier parameter. int requires name n; list[int]/str are recognized in Python, with user declaration for unannotated/JavaScript types. Defaults, async/generators, methods/classes, rest/destructuring/keyword-only parameters, duplicate names and executable top-level setup are refused. No signature is guessed from an AI answer.
4. **Entry drivers:** retain function definitions, safe literal globals and Python imports; omit demo calls and preserve source lines. Unsupported initialization/dependencies fail politely. Each run receives a fresh worker; driver/source limits and existing time/step caps apply. The supported driver is a restricted preparation of the selected function, not a claim to execute every arbitrary module unchanged.
5. **Generators:** deterministic n, descending n…1 integers, or repeated ASCII abc strings. Standard sizes 4/8/16/32/64; small 2/4/8/12/16; tiny 1/2/3/4/5. Profile and generator changes clear measured samples/fit. These are not randomized average-case measurements.
6. **Measurement:** use actual worker event counts inside functions (including traced helpers), exclude module/driver events and do not use wall time. All five traces must complete, be nonempty and uncapped before fitting. Show raw counts/table/chart, best model, normalized RMS error and next fit. Use nonnegative least-squares scale/intercept for log/n/n-log-n/n²/n³/2ⁿ candidates; identical counts yield constant. Estimates are local to tested sizes and instrumentation, not proven asymptotic bounds.
7. **Heatmaps:** count real line events only. Yellow intensity and source-line links reflect captured executions. Simulated traces are excluded; capped traces are partial evidence. Editing source clears the trace/heatmap.
8. **AI pipeline:** retain the single /api/analyze provider boundary and explicit provider/model selection. Add analysis/simulate modes with strict Zod schemas and exact source hashes, real source-line bounds and known entry references. One retry shares one total 18-second provider deadline and retains the existing 3,500-output-token ceiling. Malformed/unavailable answers fall back to local AST/traces; no invented substitute trace. No stdin, output or runtime values are uploaded, and no user code executes on the server.
9. **Advice/testing:** issue reports are possibilities, optimized code is an unverified proposal displayed as an exact bounded line-block diff with explanation and original-line references. Apply is explicit and invalidates old results. Tests contain one typed JSON argument, not executable provider-authored test code. Construct drivers from the real AST and run every supported suggestion in the real tracer before enabling its control. Failed/capped/unsupported suggestions are not runnable. AI expected outputs remain unverified even after observing a real output. Clicking Run this test runs a fresh worker again, then opens that real trace.
10. **Simulation:** C++/Java only, with explicit source-upload notice and fresh per-run consent. A source revision counter also prevents restoring consent by editing back to earlier text. Consent is never shared/persisted. No private stdin is modelled; no native runtime for these languages is claimed.
11. **Simulation validation:** same Step fields with strict bounded nested schemas, contiguous indices, actual line/frame bounds, unique invocation ids, push/pop consistency, balanced root on complete traces, cumulative output, declared own-property heap references, safe integer encodings and the requested cap. Integers beyond the safe JSON range use exact decimal strings. Reject rather than repair. No elapsed performance measurement is invented (elapsed is zero). A persistent dashed banner/view style says “AI-simulated, may be inaccurate”. Analysis/heatmaps never treat it as real execution.
12. **Deployment catalog:** preserve local SQLite maintenance and immutable history. Export a source-verified build-time JSON snapshot for Vercel, including all current and historical implementations. The remote prebuild checks a manifest of maintained source hashes and fails stale exports; it needs no Python and no runtime SQLite file. This chooses the explicitly authorized static-data alternative because a Python-generated ignored SQLite artifact is not guaranteed in remote builds. There are no ephemeral database writes or new hosted user-data stores. Local SQLite tracing remains explicit.
13. **Shared limiter:** replace process memory with one atomic Redis REST EVAL checking 5/client/minute and 30/global/minute across instances, with 60-second TTLs and a stable application namespace. All valid AI POST modes, including offline fallbacks, share the ceilings. Missing/unavailable/malformed storage fails closed with 503. Client identifiers are HMAC hashed; no source/trace is stored. At most 30 accepted client keys per global window bounds key growth; rejected requests do not create keys. Local HTTP fixture evidence is distinguished from live hosted Redis verification.
14. **Runtime/CSP/cache:** select Node 24.x, and export a 25-second analyze function allowance to accommodate the 18-second provider deadline plus the shared-store check. Keep trusted runtime assets same-origin and content-address their complete installed contents for immutable caching. Revalidate the small asset manifest. Add CSP, frame/nosniff/referrer/permissions headers. Static Next hydration needs unsafe-inline scripts; Monaco/Pyodide/JS worker execution needs eval/WASM allowances and blob workers. Inline styling is needed for these UI runtimes. This compatible CSP is explicitly not nonce-based, and worker API restrictions remain educational rather than hardened isolation.
15. **Shares:** a link fills source/language/stdin and clears earlier execution; it starts neither a worker nor an AI request. Simulation consent, traces, tests and analysis state are not encoded.
16. **Verification:** full lint, strict typecheck, real-runtime unit tests, production-build Playwright, mobile/a11y states and measured 5,000-step scripts. Performance measurement records device/environment and frame quantization, not a universal FPS guarantee. No live provider/Redis/cloud claim is inferred from local fixtures. Both Vercel connector and CLI currently reject invalid authentication, so cloud deployment remains unverified until reauthentication.

## Production AI controls

This section supersedes Phase 3's 30/global/minute limiter and credential-only readiness. AI_ENABLED defaults off. Readiness validates provider/model and Redis configuration, probes the shared EVAL and checks available quota without consuming it. The result is a point-in-time status, not a reservation or a guarantee against subsequent outages/concurrency. Each POST checks admission and each provider call (including the single validation retry) reserves budget atomically; SDK retries stay disabled. Store failure is a non-secret 503 with no provider call. Exhausted budget is a 429 with Retry-After and “AI notes are paused for today”; local AST, measurements and real traces remain available.

Defaults are 5 client requests/minute, 10 provider calls/environment/minute and AI_DAILY_LIMIT=100 calls/environment/UTC day. Keys use {stable-app-namespace:VERCEL_ENV}, default development; deployment URLs/IDs never enter the namespace. Client identifiers are HMAC hashes. Daily keys expire at the next 00:00 UTC and reservations are never refunded for uncertain provider outcomes. Prefer separate preview/production Redis databases and provider credentials. This counts calls, not dollars, and changing the namespace/store can reset counters, so keep them stable.

### Deployment checklist

1. Keep AI_ENABLED=false until server-only credentials, a supported model, validated Redis EVAL permissions and the daily ceiling are configured; rotate credentials exposed in chat. Set CODELENS_STATIC_LIBRARY=1 at build/runtime and include a fresh catalog export.
2. Isolate preview/production databases where possible; preserve one namespace per environment across instances and redeployments. Test readiness, quota exhaustion, retries and unreachable-store behavior.
3. Configure Vercel Firewall rules targeting POST /api/analyze (log first, then per-IP rate limit/challenge/deny); protect GET readiness separately at the edge and previews as well. The route has a documented admission hook for this platform protection. No spoofable header is accepted as proof of bot checks. BotID instead requires end-to-end browser/server verification.
4. Set and verify a hard spending cap in the provider dashboard before public enablement. OpenAI project spend alerts are not hard caps ([official guidance](https://developers.openai.com/api/docs/guides/terraform/rate-limits-and-spend)); if an enforcing provider/account limit is unavailable, keep AI off until an enforcing gateway is configured.
